# 개요

## 배경 및 필요성

기존 에이전트 개발 환경에서 발생하는 문제점:

* 표준화 부족: 프로젝트별로 분산된 개발 프로세스
* 운영 효율 저하: 일관된 배포·모니터링 체계 부재
* 재사용성 부족: 공통 컴포넌트 및 템플릿 미비

AI Agent Factory는 이러한 문제를 해결하기 위해 다음을 제공합니다:

* 통합된 개발 환경: 웹 기반 비주얼 에디터
* 표준화된 파이프라인: 생성부터 배포·모니터링까지 일관된 프로세스
* 재사용 가능한 자산: 템플릿, 컴포넌트 카탈로그

## 주요 특징

* Low-Code 개발: Langflow 기반 시각적 워크플로우 빌더
* Playground 통합: 사내 DevOps 플랫폼과 완전 연동
* 원클릭 배포: 간편한 배포 및 스케줄링
* 실시간 모니터링: Langfuse를 통한 추적 및 분석

# 핵심 개념

### 1. 생성/검증/배포/모니터링 파이프라인

에이전트의 전체 라이프사이클을 일관되게 관리합니다.

#### 개발 단계
1.  Flow 생성: 비주얼 에디터에서 컴포넌트를 연결하여 워크플로우 작성
2.  테스트 실행: 캔버스에서 바로 테스트하여 결과 확인
3.  디버깅: 각 컴포넌트별 입출력 확인 및 문제 해결

#### 배포 단계
1.  Playground 배포: 클릭 한 번으로 Kubernetes 환경에 배포
2.  Ingress 설정: 자동 URL 할당 및 라우팅 구성
3.  스케줄링: 배치 작업을 위한 주기적 실행 설정

#### 운영 단계
1.  상태 모니터링: Running/Building/Error 상태 실시간 확인
2.  로그 조회: Pod 로그 및 에러 추적
3.  성능 분석: Langfuse를 통한 응답 시간, 토큰 사용량 분석

---

### 2. 운영 대시보드

모든 에이전트를 한 곳에서 통합 관리합니다.

#### 대시보드 기능
* 에이전트 목록: 배포된 모든 에이전트 현황 조회
* 상태 관리: 시작/중지/재시작 제어
* 로그 조회: 실시간 로그 및 이력 확인
* 스케줄 관리: Cron 기반 스케줄 설정

---

### 3. 표준 워크플로우·템플릿

재사용 가능한 템플릿과 컴포넌트로 개발 생산성을 높입니다.

#### 제공 템플릿
* RAG Agent: Confluence 문서 기반 질의응답 에이전트
* MCP Agent: MCP 도구를 활용한 범용 에이전트
* Data Analysis Agent: IDCube 데이터 분석 에이전트

### 커스텀 컴포넌트

Playground 전용 컴포넌트를 통해 사내 시스템과 쉽게 연동:

* Playground Model / Agent / Embedding
* Playground Qdrant (벡터 DB)
* Confluence to Qdrant Sync
* IDCube Athena, EMAIL, TOKTOK 등

자세한 내용은 커스텀 컴포넌트 가이드 문서를 참조하세요.

## Input / Output

### Chat Input
* 채팅 메시지를 입력받는 컴포넌트
* 사용 방법: 플로우에 드래그 후 에이전트·채팅 노드의 입력과 연결한다. 채팅 UI에서 사용자가 입력한 메시지가 이 컴포넌트 출력으로 전달된다. 보통 플로우의 시작 노드로 사용한다.

### Chat Output
* 채팅 메시지를 출력하는 컴포넌트
* 사용 방법: LLM 또는 에이전트의 응답 출력을 이 컴포넌트의 입력에 연결한다. 연결된 메시지가 채팅 UI에 표시된다. 플로우의 마지막 노드로 두는 경우가 많다.

### Text Input
* 텍스트를 입력받는 컴포넌트
* 사용 방법: 컴포넌트 설정에서 기본값(Default Value)을 지정하거나, API/배치 실행 시 입력 필드로 값을 넘긴다. 다른 노드의 입력 포트에 연결해 사용한다.

### Text Output
* 텍스트를 출력하는 컴포넌트
* 사용 방법: 전처리·LLM 등 이전 노드의 텍스트 출력을 이 컴포넌트 입력에 연결한다. 결과는 Run 결과 패널 또는 API 응답으로 확인할 수 있다.

다섯 번째 이미지의 내용을 추출하여 원본의 레이아웃과 서식에 맞춰 정리해 드립니다.

## Agent
* LLM과 도구를 조합하여 대화형 에이전트를 구성하는 컴포넌트
* 사용 방법: Language Model 컴포넌트와 필요한 Tools(MCP, Web Search 등)를 Agent에 연결한다. 시스템 프롬프트와 온도 등 파라미터를 설정한 뒤, Chat Input과 연결해 대화형 플로우를 만든다.

### MCP Tools
* MCP(Model Context Protocol) 서버의 도구를 호출하는 컴포넌트
* 사용 방법: MCP 서버 URL 및 설정을 입력하고, Agent 컴포넌트의 Tools 입력에 연결한다. 서버에서 제공하는 도구 목록이 로드되면 플로우 실행 시 에이전트가 해당 도구를 호출할 수 있다.

### Playground Agent
* Playground 환경에 최적화된 에이전트 컴포넌트
* 사용 방법: Playground에 배포된 모델·도구 설정을 그대로 사용한다. Agent와 동일하게 Chat Input·Model·Tools를 연결해 구성하며, Playground 전용 인증·엔드포인트가 적용된다.

여섯 번째 이미지의 내용을 추출하여 원본의 레이아웃과 서식에 맞춰 정리해 드립니다.

## Data

### API Request
* REST API 요청으로 데이터를 가져오는 컴포넌트
* 사용 방법: URL·HTTP 메서드(GET/POST 등)·헤더·바디를 설정한다. 쿼리 파라미터는 변수로 넣을 수 있으며, 출력을 다른 노드로 전달해 파싱·가공에 사용한다.

### Directory
* 디렉터리 경로의 파일 목록 또는 내용을 읽는 컴포넌트
* 사용 방법: 읽을 디렉터리 경로를 지정하고, 필요 시 파일 패턴(예: `*.txt`)이나 인코딩을 설정한다. 출력은 파일 목록 또는 결합된 텍스트로, Parser·Split Text 등과 연결한다.

### File
* 파일을 읽어 데이터로 사용하는 컴포넌트
* 사용 방법: 파일 경로를 직접 입력하거나 이전 노드 출력을 경로로 연결한다. 인코딩·라인 제한을 설정할 수 있으며, 읽은 내용은 다음 노드로 전달한다.

### News Search
* 뉴스 검색 결과를 가져오는 컴포넌트
* 사용 방법: 검색 쿼리·언어·건수 등을 설정한다. 쿼리는 고정값 또는 이전 노드 출력으로 넘길 수 있다. 결과는 에이전트 컨텍스트나 요약 입력으로 활용한다.

### RSS Reader
* RSS 피드를 읽는 컴포넌트
* 사용 방법: RSS 피드 URL을 입력하고, 가져올 항목 수 등을 설정한다. 출력된 항목 목록을 LLM·Parser와 연결해 요약·필터링에 사용한다.

### SQL Database
* SQL 데이터베이스에 쿼리를 실행하는 컴포넌트
* 사용 방법: DB 연결 정보(URL·계정 등)와 실행할 SQL을 설정한다. SQL은 고정 문자열이거나 이전 노드 출력(동적 쿼리)으로 연결할 수 있다. 결과는 Data-Frame·파싱 노드로 전달한다.

### URL
* URL에서 콘텐츠를 가져오는 컴포넌트
* 사용 방법: 가져올 URL을 입력(고정값 또는 이전 노드 출력)하고, 필요 시 헤더를 설정한다. HTML 등은 Parser와 연결해 텍스트만 추출해 사용한다.

### Web Search
* 웹 검색 결과를 가져오는 컴포넌트
* 사용 방법: 검색 쿼리를 설정(고정 또는 변수 연결)하고, 결과 개수 등을 지정한다. 에이전트의 Tool로 쓰거나, 검색 결과를 컨텍스트로 넘겨 RAG처럼 활용한다.

### Webhook
* 웹훅으로 외부 요청을 수신하는 컴포넌트
* 사용 방법: 플로우를 API로 배포한 뒤 부여되는 Webhook URL을 외부 시스템에 등록한다. 해당 URL로 들어온 요청 본문·헤더가 컴포넌트 출력으로 전달되며, 이후 노드에서 처리한다.

일곱 번째 이미지의 내용을 추출하여 원본의 레이아웃과 서식에 맞춰 정리해 드립니다.

## Processing

### Prompt Template
* 프롬프트 템플릿으로 메시지를 구성하는 컴포넌트
* 사용 방법: 템플릿 문자열에 `{{변수명}}` 형태로 플레이스홀더를 넣는다. 변수는 입력 포트로 연결된 노드 출력과 매핑하며, Language Model의 입력에 연결해 최종 프롬프트를 전달한다.

### Batch Run
* 여러 입력에 대해 플로우를 배치 실행하는 컴포넌트
* 사용 방법: 반복할 입력 목록(리스트)을 이 컴포넌트에 연결하고, 실행할 하위 플로우 또는 노드 체인을 지정한다. 각 항목에 대해 플로우가 순차 실행되며 결과가 리스트로 모인다.

### Data Operations
* 데이터 변환·필터링 등 데이터 연산을 수행하는 컴포넌트
* 사용 방법: 입력 데이터를 연결한 뒤, 필드 선택·필터 조건·정렬·집계 등 연산 종류와 옵션을 설정한다. 출력을 다른 Data·Processing 노드로 전달한다.

### Data-Frame Operations
* DataFrame 기반 데이터 연산을 수행하는 컴포넌트
* 사용 방법: DataFrame을 반환하는 노드(SQL Database, API 등)의 출력을 입력으로 연결한다. 컬럼 연산·조인·피벗 등 설정 후 결과 DataFrame을 다음 노드로 넘긴다.

### LLM Reader
* LLM을 사용해 문서 등을 읽고 요약·추출하는 컴포넌트
* 사용 방법: 읽을 텍스트·문서를 입력에 연결하고, 사용할 Language Model을 지정한다. 요약·QA·키워드 추출 등 태스크를 선택하면 LLM 결과가 출력으로 나간다.

### Parser
* 텍스트·문서 등을 파싱하는 컴포넌트
* 사용 방법: 파서 타입(JSON, HTML, Markdown 등)을 선택하고, 파싱할 문자열을 입력에 연결한다. 추출된 구조화 데이터나 텍스트를 다음 노드에서 사용한다.

### Python Interpreter
* Python 코드를 실행하는 컴포넌트
* 사용 방법: 실행할 Python 코드를 입력하고, 입력 변수는 이전 노드 출력을 연결해 사용한다. `result` 등 지정된 변수가 출력으로 전달되며, 샌드박스 환경에서 실행된다.

### Save File
* 결과를 파일로 저장하는 컴포넌트
* 사용 방법: 저장할 내용을 입력 포트에 연결하고, 파일 경로(또는 경로를 반환하는 이전 노드)와 인코딩을 설정한다. 플로우 실행 시 해당 경로에 파일이 생성된다.

### Smart Function
* 조건·로직에 따른 스마트 함수 실행 컴포넌트
* 사용 방법: 조건식과 참/거짓일 때 실행할 동작(또는 연결할 노드)을 설정한다. 입력 값을 평가한 뒤 분기 결과를 출력으로 내보낸다.

### Split Text
* 텍스트를 분할하는 컴포넌트
* 사용 방법: 분할할 텍스트를 입력에 연결하고, 구분자(쉼표, 줄바꿈 등) 또는 청크 크기·오버랩을 설정한다. 분할된 문자열 리스트를 VectorDB 임베딩·배치 처리 등에 사용한다.

여덟 번째 이미지의 내용을 추출하여 원본의 레이아웃과 서식에 맞춰 정리해 드립니다. 하단의 컴포넌트 그리드 이미지에 포함된 텍스트도 함께 정리했습니다.


### Structured Output
* 구조화된 형식(JSON 등)으로 출력을 만드는 컴포넌트
* 사용 방법: 스키마(JSON Schema) 또는 출력 필드를 정의하고, LLM 출력을 이 컴포넌트에 연결한다. LLM이 스키마에 맞게 생성하도록 유도하며, 파싱된 객체를 다음 노드로 전달한다.

### Type Convert
* 데이터 타입을 변환하는 컴포넌트
* 사용 방법: 변환할 값을 입력에 연결하고, 목표 타입(string, number, list, dict 등)을 선택한다. 형식이 맞지 않으면 오류가 나므로 이전 노드 출력 형식을 확인한다.
