# Azure AI Search

# 1) Azure AI Search 한눈에 보기

Azure AI Search는 **문서·데이터를 인덱싱해 고품질 검색 API를 제공**하는 PaaS입니다. 전통적인 **키워드(전체 텍스트)** 검색에 더해 **벡터 검색**과 **의미 체계(semantic) 재랭킹**을 지원하고, 둘을 **한 번의 요청에서 병렬 실행해 RRF(Reciprocal Rank Fusion)로 결과를 융합**하는 **하이브리드 검색**을 기본 패턴으로 제공합니다. ([Microsoft Learn][1])

요약하면:

* **키워드(BM25)** + **벡터(HNSW 또는 KNN)** + (선택) **Semantic Ranker**를 조합해 가장 관련도 높은 결과를 반환합니다. 하이브리드 쿼리의 결과 병합에는 **RRF**가 사용됩니다. ([Microsoft Learn][2])

# 2) 핵심 개념과 아키텍처

* **인덱스(Index)**: 검색의 스키마(필드, 분석기, 벡터 필드 등).
* **데이터 소스(Data source)**: Blob, ADLS, Cosmos DB, SQL 등 외부 저장소 연결.
* **인덱서(Indexer)**: 외부 데이터 → 인덱스로 **동기화**하는 배치 파이프라인. 증분/스케줄링 가능. **스킬셋(Skillset)** 실행의 컨트롤러 역할을 합니다. ([Microsoft Learn][3])
* **스킬셋/AI 보강(Enrichment)**: OCR, 언어 감지, 키 프레이즈 추출, 요약, 사용자 정의 스킬 호출 등으로 **비정형 원본을 검색 친화 구조로 변환**합니다. ([Microsoft Learn][4])
* **벡터 필드/벡터 인덱스**: 임베딩을 저장·조회. **HNSW(ANN)** 또는 **Exhaustive KNN**로 근접 이웃을 찾고 유사도 점수로 랭킹합니다. ([Microsoft Learn][5])
* **Semantic Ranker**: MS의 LLM 기반 언어 이해로 **상위 후보를 재정렬**하여 관련도를 올려주는 **사용량 과금형 프리미엄 기능**. ([Microsoft Learn][6])
* **하이브리드 검색**: **search(키워드)** 와 **vectors(벡터)** 파라미터를 **한 요청**에 담아 **병렬 실행 → RRF 융합**. 보통 가장 높은 품질을 제공합니다. ([Microsoft Learn][7])

# 3) 인덱싱 파이프라인(내부/외부 벡터화)

벡터 검색을 쓰려면 임베딩이 필요합니다. 두 가지 경로가 있습니다.

1. **내부 처리(통합 벡터화)**: 인덱서 파이프라인에서 **자동 청크+임베딩**(예: Azure OpenAI 연결)까지 **내부에서 처리**. 데이터 소스·인덱서·스킬셋이 필요합니다. ([Microsoft Learn][8])
2. **외부 처리**: 앱/ETL에서 미리 청크·임베딩 생성 후 **벡터 필드에 직접 업서트**. ([Microsoft Learn][8])

> 참고: 학습·실습을 위해 **하루 20문서/인덱서 무료 보강 할당**이 제공됩니다(일부 보강은 항상 무료). ([Azure 문서][9])

# 4) 검색 모델별 동작 방식

## 4.1 키워드(텍스트) 검색

* **BM25/필터/패싯/정렬/점수 프로파일** 등 전통 기능. 하이브리드 요청에서도 그대로 활용됩니다. ([Microsoft Learn][2])

## 4.2 벡터 검색

* 벡터 필드에 대해 **HNSW(ANN)** 또는 **Exhaustive KNN**으로 근접 이웃을 찾고, **코사인/유클리드 등 유사도**로 랭킹합니다. ([Microsoft Learn][5])
* 쿼리 시 입력도 같은 임베딩 모델로 **인코딩**해야 포함 공간이 일치합니다. ([Microsoft Learn][10])

## 4.3 하이브리드 검색

* 단일 요청에 `search=...`(키워드)와 `vectors=[...]`(벡터) 동시 전달 → **병렬 실행 후 RRF로 병합**. 벡터/키워드의 **가중치**와 **Semantic Ranker**를 조합해 품질을 끌어올릴 수 있습니다. ([Microsoft Learn][1])

## 4.4 Semantic Ranker(의미 체계 재랭킹)

* 상위 N개 후보를 LLM 기반 모델이 **문맥적으로 재정렬**하여 **측정 가능한 관련도 향상**. 사용량 과금의 프리미엄 기능. ([Microsoft Learn][6])

# 5) 스키마/설계 포인트

* **문서 ID**는 안정적·불변 키로.
* **텍스트 원문**과 **청크 필드**를 분리(원문 보존, 청크 검색·RAG용).
* **벡터 필드**: `dimensions`, `vectorSearchConfiguration` 지정.
* **필터링용 구조화 필드**(카테고리, 태그, 날짜 등) 별도 분리.
* **하이브리드** 대비: 동일 인덱스에 텍스트 필드와 벡터 필드를 **함께** 둡니다. ([Microsoft Learn][8])

# 6) 운영·보안

* **가상 네트워크·Private Endpoint**, **RBAC**, **키 관리(암호화)**, **검색 트래픽 제한/쿼터 관리** 등을 조합. **서비스·SKU별 한도**는 공식 표를 확인하세요. ([Microsoft Learn][11])
* Azure 전반 **구독/서비스 한도**는 별도 문서를 참고. ([Microsoft Learn][12])

# 7) 성능·튜닝 팁

* **하이브리드+Semantic Ranker 조합**이 다수 벤치마크에서 높은 품질(관련도)을 보입니다. ([Microsoft Learn][7])
* **HNSW 파라미터**(m, efConstruction, efSearch)와 **KNN 스캔 범위**를 워크로드에 맞게 조정. 벡터 차원/정규화 일관성 유지. ([Microsoft Learn][5])
* **maxTextRecallSize**(텍스트 회수 폭)와 **벡터·키워드 가중치**로 하이브리드 균형 최적화. ([Azure 문서][13])
* 인덱서 증분·스케줄링으로 **동기화 지연 최소화**; 대량 적재는 배치 업서트 병행. ([Microsoft Learn][3])

# 8) 비용·용량·SKU

* **SKU(예: Basic, S1~S3, L1~)**에 따라 **스토리지/인덱스 수/스킬셋/동시성 한도**가 달라집니다(정확 수치는 공식 한도표 참고). 서비스는 **티어별로 지역당 최대 개수** 등 제한이 있습니다. ([Microsoft Learn][11])
* **Semantic Ranker**는 **사용량 기반 비용**. **AI 보강**은 대부분 Azure AI Services 과금이나, **실습용 무료 할당**이 일부 제공됩니다. ([Microsoft Learn][6])

# 9) RAG 통합 패턴(요지)

1. 원문 → 청크화 → 임베딩 → 인덱싱(텍스트+벡터).
2. 쿼리 시 **하이브리드 검색**으로 상위 K 청크를 회수.
3. (선택) **Semantic Ranker** 재정렬 후 상위 N을 LLM에 **컨텍스트 주입**.
4. 답변 생성/요약/추출. (Azure OpenAI 쿼터·한도는 별도 문서 참고) ([Microsoft Learn][7])

# 11) 하이브리드 쿼리 예시(REST 느낌)

핵심은 **한 요청**에 텍스트와 벡터를 같이 보내는 것입니다.

```http
POST https://<search-service>.search.windows.net/indexes/<index>/docs/search?api-version=2024-11-01
api-key: <admin-or-query-key>
Content-Type: application/json

{
  "search": "azure openai foundry tutorial",
  "vectors": [
    {
      "value": [/* 쿼리 임베딩 벡터 */],
      "fields": "contentVector",
      "k": 20
    }
  ],
  "top": 10,
  "queryType": "semantic",           // Semantic Ranker 사용
  "semanticConfiguration": "default", // 사전 구성 이름
  "scoringProfile": null,
  "answers": "extractive|count-3",    // (선택) 추출형 답변
  "captions": "extractive"            // (선택) 캡션
}
```

> 하이브리드 요청의 **병렬 실행 + RRF 융합**과 **추가 파라미터(가중치/회수 크기)** 는 공식 “하이브리드 검색” 가이드를 참고하세요. ([Microsoft Learn][7])

# 13) Python 스니펫(요약)

> 실제 SDK 버전·API 버전은 환경에 맞게 조정하세요.

```python
from azure.core.credentials import AzureKeyCredential
from azure.search.documents.indexes import SearchIndexClient
from azure.search.documents.indexes.models import (
    SearchIndex, SimpleField, SearchableField, VectorSearch,
    HnswAlgorithmConfiguration, VectorSearchAlgorithmConfiguration, 
    VectorSearchProfile, VectorField
)
from azure.search.documents import SearchClient

service_endpoint = "https://<service>.search.windows.net"
admin_key = "<admin-key>"
index_name = "docs"

# 1) 인덱스 스키마(텍스트 + 벡터)
vector_search = VectorSearch(
    algorithms=[
        HnswAlgorithmConfiguration(name="hnsw-default")
    ],
    profiles=[
        VectorSearchProfile(name="vec-profile", algorithm_configuration_name="hnsw-default")
    ]
)

fields = [
    SimpleField(name="id", type="Edm.String", key=True),
    SearchableField(name="title", type="Edm.String"),
    SearchableField(name="content", type="Edm.String"),
    VectorField(name="contentVector", searchable=True, dimensions=1536, vector_search_profile_name="vec-profile")
]

index = SearchIndex(name=index_name, fields=fields, vector_search=vector_search)
idx_client = SearchIndexClient(service_endpoint, AzureKeyCredential(admin_key))
try:
    idx_client.delete_index(index_name)
except:
    pass
idx_client.create_index(index)

# 2) 문서 업서트(벡터는 외부에서 생성했다고 가정)
docs = [
    {"id":"1","title":"Getting started","content":"Azure AI Search overview ...","contentVector":[...]}
]
search_client = SearchClient(service_endpoint, index_name, AzureKeyCredential(admin_key))
search_client.upload_documents(docs)

# 3) 하이브리드 검색(키워드 + 벡터)
query_vector = [...]  # 동일 임베딩 모델로 인코딩
results = search_client.search(
    search_text="azure ai search quickstart",
    vectors=[{"value": query_vector, "k": 20, "fields": "contentVector"}],
    top=10
)
for r in results:
    print(r["id"], r["@search.score"])
```

# 14) 자주 묻는 질문(FAQ)

**Q1. 벡터만으로 충분한가요?**
A. 다수의 실제 데이터셋에서 **하이브리드(+Semantic)** 가 가장 안정적인 품질을 냅니다. 키워드 필터/패싯과 결합도 용이합니다. ([Microsoft Learn][7])

**Q2. 임베딩은 어디서 생성?**
A. **내부 인덱서 파이프라인**(청크+벡터화 통합) 또는 **외부 생성 후 업서트** 중 선택. PoC는 내부가 간편합니다. ([Microsoft Learn][8])

**Q3. 어떤 ANN 알고리즘을 쓰나요?**
A. **HNSW**(Approximate)와 **Exhaustive KNN**을 지원합니다. ([Microsoft Learn][5])

**Q4. 비용은 어떻게 계산?**
A. 서비스 **SKU/용량** + (선택) **Semantic Ranker 사용량** + (선택) **AI 보강 과금**이 합산됩니다. **한도/제약**은 공식 표를 확인하세요. ([Microsoft Learn][11])
